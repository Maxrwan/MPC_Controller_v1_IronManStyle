# Control analysis — useful early diagnostics and retained deeper work

Sources/revisions: [W/P/C/F/S ledger](ENGINEERING_CAPABILITY_AUDIT.md). These are capability/design
definitions, not new numerical results. Canonical state is `[vx,vy,r,e_psi,s_abs,e_y]`, inputs
`[delta,a_cmd]`; dynamic `a_cmd=Fx/m`, not generally `dvx/dt`. Plant, prediction, design and measurement
models must remain distinguishable. No new rank, convergence, stability or physical threshold is set.

Early engineering value is concrete: expose already exported references/gains/saturation and the
accepted summary windows, then make recorded solver/deadline failures inspectable. None needs a
new independent physics engine. Baseline poles/conditioning must name their design model and speed;
TVLQR plots must name their packet/map/time. Plant-to-track, plant-to-packet and Planning-to-APEX
errors are different quantities and cannot share an unlabeled “tracking error” score.

The deeper Control Performance & Systems Analysis goal remains substantive: after C/F review and
execution gates, integrate their source-bound outputs into the same inspector. Do not build a second
analysis engine, retune their criteria, or substitute W's functional test result for their scientific
qualification. See [scientific decisions](DECISIONS_AND_NEXT_TASK.md#scientific-decisions-only-when-needed).
